# M9 Full Discord: report

Finished 2026-11-20, on the user's own tests on the TV PC (real account) and a full end-to-end batch there.

## What M9 is

One Discord integration: the Dashboard's own hidden discord.com web session (WebView2, one per Profile). Everything is
read from Discord's in-page Flux stores and pushed on their change events; actions go by id through a paced, one at a
time queue (docs/discord-web.md: Reading, Acting, Voice). The local RPC connection and the Discord app are retired
(#299, #318): Settings > Account has one Discord page, the web session's.

Lessons from the real page (2026-11-19 to 20), kept in docs/discord-web.md: about 99 catch-all objects on discord.com
answer any name with a do-nothing function, so a search by shape must skip them; some action modules load only once the
chat is used; the real page has none of the action names (`createPendingReply`, `addReaction`, `ack`), so the page
script dispatches or finds functions by their source; and a copy of an unsigned exe can be blocked by Smart App Control
right after the TV wakes (the reputation check had no network), and is allowed a minute later.

## The full TV batch (2026-11-20, main at 3276043)

57 payloads in safe mode: 52 passed, 5 failed. #320 fixed four of them, each passing on a rerun on the TV:

- `discord-dms`, `discord-web-voice`, `launch-backdrop`: the `guide:` focus log line was said only around a press, so
  a change with no press (a message arriving, a conversation loading, a game ending behind the Guide) was silent. The
  line is now said wherever in a turn it changes. The two Discord payloads also had wrong expectations (the DM a
  message arrives in moves to the top; the Call's entries run down, not across).
- `mixed`: Battle.net's fake has no `catalog_cache`; the payload now allows the source's `owned: not known/taken` lines.

Left failing: `install` needs a staged `XboxSeriesDashboard-<version>-setup.exe`, which CI's Package job cannot make
while the artifact storage quota is full.
